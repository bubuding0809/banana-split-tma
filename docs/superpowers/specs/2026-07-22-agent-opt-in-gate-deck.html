Per-Group AI Agent
Opt-In Gate

Design spec · 2026-07-22 · banana-split-tma

experimental feature approved design

Problem

The bot's AI agent fires in every group by default — mentions, replies, /ask, /do.

Feature is experimental and flaky. Groups must opt in explicitly; default is off for all groups.

Confirmed decisions

QuestionDecision
ScopeGroup chats only — DMs stay AI-on
Disabled behaviorSilent ignore, no hint reply
UI placementNew "Bot" subpage under Group settings
DefaultOff everywhere, including existing groups

Approach: boolean on Chat

A · Chat column chosen

Follows existing toggle pattern (debtSimplificationEnabled, notifyOn*). One migration, same plumbing everywhere.

B · Feature-flag table rejected

Generic ChatFeatureFlag — overkill for one flag, new query paths.

C · Env allowlist rejected

No self-serve opt-in — fails the requirement.

1 · Database

model Chat {
  // ...existing toggles
  debtSimplificationEnabled Boolean @default(false)
  agentEnabled              Boolean @default(false) // NEW
}

Migration backfills false — every existing group starts gated. DM rows carry the column but the DM path never reads it.

2 · tRPC

  • getChat output → agentEnabled (defaults false)
  • updateChat → optional agentEnabled in input, plumbing, output
  • Access unchanged: assertChatAccess, any member can toggle — same as every other group setting

3 · Bot gate

Entry pointGated?
Group mention / reply-to-bot (group.ts:238)gated
/ask · /do in groupsgated
Private DM auto-handle (agent.ts:387)untouched

Check via ctx.trpc.chat.getChat only on would-trigger messages. Disabled → silent return + agent.gated log.

4 · TMA UI

  • Settings hub → Group section gets "Bot" RowLink, preview "AI on" / "AI off"
  • New route /chat/$chatId/settings/bot
  • BotSettingsSubPage: one Switch cell "AI assistant" + description
  • telegram-ui components, Event-alerts subpage pattern: optimistic mutation, haptics, back button

Error handling

Fail closed. If the bot's getChat lookup errors, treat as disabled and log — a flaky experimental feature should not fire on error.

TMA toggle: standard optimistic-revert on mutation error.

Testing

  • updateChat: round-trip + omitted-field no-op
  • Bot: gated mention → silence · opted-in mention → agent · /ask gated in group, free in DM · lookup failure → silence
  • Manual UAT: toggle in TMA → mention (silence) → enable → mention (response) → DM unaffected

Out of scope

CLI, Raycast, MCP surfaces unchanged. tRPC field available to them; no commands/UI added (avoids CLI version-bump churn).
